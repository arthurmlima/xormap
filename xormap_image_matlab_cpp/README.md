# xormap image cipher: native C++17 port

This directory is a native C++17 conversion of every function, test, and
evaluation workflow in [`../xormap_image_matlab`](../xormap_image_matlab).
It does not invoke MATLAB and does not require a MATLAB Runtime. The cipher,
SHA-256 seed expansion, TIFF handling, metrics, downloads, sweeps, analyses,
and parallel task scheduling all run in C++.

The implementation keeps both forms of the XOR-map transform:

- a direct canonical translation used as the reference implementation; and
- the equivalent prefix-XOR fast path used for full-image work.

The fast path is checked against the canonical path and against golden vectors
generated by the unmodified MATLAB R2026a sources. See
[`docs/MATLAB_PORT_MAP.md`](docs/MATLAB_PORT_MAP.md) for the complete file-by-file
port map.

## Requirements on macOS

Apple Clang from the Xcode Command Line Tools is the C++ compiler. Install it
once if `clang++ --version` is not already available:

```sh
xcode-select --install
```

Install the build and native library dependencies system-wide with Homebrew:

```sh
brew install cmake openssl@3 libtiff catch2 pkgconf curl cairo poppler
```

The dependencies are:

- CMake 3.20 or newer and a C++17 compiler;
- OpenSSL 3 for SHA-256 through its EVP API;
- libtiff for strict, native 8-bit grayscale TIFF input/output;
- libcurl for USC-SIPI downloads;
- Cairo with its PDF surface for native vector reports;
- Catch2 3 for the test executables; and
- the standard C++ threads library for native parallel work.

Poppler is used by the development/verification workflow to inspect and render
every generated PDF; it is not required by the executable at runtime.

## Build and test

From this directory:

```sh
cd /Users/arthur/xormap/xormap_image_matlab_cpp
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release \
  -DOPENSSL_ROOT_DIR="$(brew --prefix openssl@3)" \
  -DCURL_ROOT="$(brew --prefix curl)"
cmake --build build --parallel
ctest --test-dir build --output-on-failure
```

The explicit Homebrew roots avoid accidentally selecting an incompatible
system OpenSSL or curl. On a machine where CMake already finds the intended
libraries, the shorter configure command is also sufficient:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
```

The included Makefile wraps the same workflow:

```sh
make test
```

For a library/CLI-only build without Catch2, configure with
`-DBUILD_TESTING=OFF`. The executable is `build/xormap_gray`.

## Existing image corpus

By default the CLI reads
`../xormap_image_matlab/images`. That sibling directory already contains the
159-image USC-SIPI grayscale corpus and `manifest_gray.csv`, so the TIFF data
is reused in place rather than copied into this project. C++ results go to this
project's own `results/` directory.

Use `--images DIR`, `--manifest CSV`, or `--results DIR` to override those
locations. The CLI locates the project at runtime when launched from the
project root, its build directory, or the parent workspace. An installed copy
uses the invocation directory and has no baked-in source-tree path. Set
`XORMAP_IMAGE_CPP_ROOT` to an explicit project root when launching elsewhere.

If the corpus is absent or needs to be refreshed, the downloader can fetch the
three small benchmark images or all 159 native grayscale images:

```sh
./build/xormap_gray download
./build/xormap_gray download --all --threads 0
./build/xormap_gray download --all --overwrite --images /path/to/images
```

`--all` validates every TIFF as native, single-channel, unsigned 8-bit data
and writes `manifest_gray.csv` with
`filename,volume,name,height,width,channels`. Existing files are retained
unless `--overwrite` is supplied, but are still validated. Downloads use a
temporary `.part` file and are renamed only after both a successful transfer
and native grayscale-TIFF validation. The all-image command publishes no new
manifest and exits with failure if any of the 159 entries fails.

## CLI

Print the built-in command summary with:

```sh
./build/xormap_gray help
```

### MATLAB parity verification

```sh
./build/xormap_gray verify
```

This executes the assertions translated from `test_xormap_gray_fast.m`: the
canonical and fast transforms agree on complete linear bases, aligned and
unaligned keystream lengths agree byte-for-byte, canonical and fast encryption
produce identical seeds and ciphertext, decryption recovers the original
bytes, and the iteration count is `ceil(num_bytes * 8 / K)`.

The Catch2 suite adds fixed MATLAB R2026a goldens for the SHA-256 KDF, both
MATLAB random streams used by the original scripts, the reproducible
`secret_key`, keystreams at several aligned and unaligned `K` values,
encryption seeds, ciphertext bytes, image layout, and metric results.
Run only the CLI integration check with:

```sh
ctest --test-dir build -R integration::matlab_fast_path --output-on-failure
```

### Three-image evaluation (`run_all.m`)

```sh
./build/xormap_gray run-all
./build/xormap_gray run-all --k-first 512 --samples 3000 --threads 0
```

The command evaluates `boat.512`, `5.1.09`, and `7.1.01`, checks the exact
round trip, and computes entropy, horizontal/vertical/diagonal adjacent-pixel
correlation, NPCR, and UACI. `--k-first` selects the single `K` value for this
command; the default is 512.

### Three-image K sweep (`sweep_k.m`)

```sh
./build/xormap_gray sweep
./build/xormap_gray sweep --k-first 8 --k-step 4 --k-last 512 \
  --samples 3000 --threads 0
```

The default grid is `K = 8:4:512`, matching MATLAB. Each `(image, K)` task
performs both plaintext variants and records the statistical metrics and
elapsed time.

### All-image K sweep (`sweep_k_gray_all.m`)

```sh
./build/xormap_gray sweep-all
./build/xormap_gray sweep-all --k-first 24 --k-step 24 --k-last 384 \
  --manifest ../xormap_image_matlab/images/manifest_gray.csv --threads 0
```

The default grid is `K = 24:24:384` over all manifest images. `--threads 0`
means hardware concurrency; a positive number sets an explicit worker count.

### Key-sensitivity, histogram, and PSNR analysis (`analysis_gray.m`)

```sh
./build/xormap_gray analysis
./build/xormap_gray analysis --k-first 24 --k-step 24 --k-last 384 \
  --threads 0
```

This runs the shared analysis pass once for each `(image, K)` pair and the
key-bit-position study. It covers one-bit key sensitivity, wrong-key
decryption, chi-square histogram uniformity, plain/cipher PSNR, and exact
round-trip PSNR.

### Read and compare sweep CSVs

```sh
./build/xormap_gray read-sweep gray
./build/xormap_gray read-sweep rgb888
./build/xormap_gray read-sweep /path/to/sweep.csv

./build/xormap_gray compare
./build/xormap_gray compare \
  --gray results/sweep_k_gray_all.csv \
  --rgb ../xormap_image_rgb888_matlab/results/sweep_k_rgb888.csv \
  --output results/comparison/compare_rgb_gray_summary.csv
```

`read-sweep` detects the grayscale and RGB888 CSV dialects and prints one
normalized schema: image, volume, K, dimensions, pixel count, entropy,
horizontal correlation, NPCR, UACI, and time. `compare` aligns shared K values
and writes per-K aggregate data. Compact positional overrides are also
accepted as `compare [gray.csv [rgb.csv [output.csv]]]`.

Entropy and horizontal correlation are directly comparable between the two
sweeps. NPCR and UACI are not measured over the same symbol alphabet: the
grayscale sweep uses 8-bit pixels while RGB888 uses packed 24-bit words. Read
each against its own ideal values reported by the normalized sweep metadata.

## Native parallelism

The converted parallel workflows stay in C++; they do not call MATLAB,
Python, shell workers, or an external job runner. A dynamically scheduled
`std::thread` worker pool executes downloads, sweep tasks, all-image analysis,
and the bit-position study. Dynamic scheduling balances the mixed SIPI image
dimensions, while results are written in a deterministic task order after all
workers join. The first worker error cancels new work, joins every thread, and
is rethrown to the CLI.

Use `--threads 1` for serial execution, a positive value for a fixed limit, or
`--threads 0` for `std::thread::hardware_concurrency()`.

## Output artifacts

Unless `--results DIR` is supplied, artifacts are written under `results/`.

| Command | Artifacts |
|---|---|
| `run-all` | `results.md`; for each image, plain/cipher/recovered TIFFs, histogram/correlation CSVs, and `<tag>_{images,histogram,correlation}.pdf` |
| `sweep` | `sweep_k.csv` and `sweep_k.pdf` |
| `sweep-all` | `sweep_k_gray_all.csv` and `sweep_k_gray_all.pdf` |
| `analysis` | Four analysis CSVs plus `key_sensitivity_gray.pdf`, `histogram_analysis_gray.pdf`, and `psnr_analysis_gray.pdf` |
| `compare` | Summary CSV plus `compare_rgb_gray_{entropy,correlation,npcr_uaci}.pdf` in its directory |
| `download --all` | `manifest_gray.csv` beside the downloaded TIFFs |

The sweep and analysis CSV column names match their MATLAB counterparts. The
three-image `sweep_k.csv` contains
`image,K,entropy_cipher,corrH_cipher,corrV_cipher,corrD_cipher,npcr,uaci,seconds`.
The all-image `sweep_k_gray_all.csv` contains image/volume/dimension metadata,
iteration and pixels-per-iteration counts, entropy, absolute horizontal
correlation, NPCR, UACI, and time for the two encryptions. The analysis CSVs
retain the MATLAB schemas for key sensitivity, per-bit sensitivity,
chi-square uniformity, and PSNR.

For `run-all`, histogram data are emitted as
`gray_level,plain_count,cipher_count`, and correlation samples as
`sample,plain_x,plain_y,cipher_x,cipher_y`. The three TIFFs make the exact
plain/cipher/recovered byte data independently inspectable.

## Numerical parity and limitations

Cipher compatibility is byte-exact where it matters: LSB-first bit packing,
the one-byte counter-mode SHA-256 expansion, MATLAB's fixed demo-key
generation, row-major keystream layout, register advance order, seed,
ciphertext, and round trip are covered by canonical/fast and golden-vector
tests.

The port preserves MATLAB R2026a's context-dependent random streams. Serial
client workflows use `mt19937ar` (Twister), while the original `parfor` worker
paths use `threefry4x64_20`; a bare `rng(seed)` reseeds whichever generator is
active. Both generators, MATLAB's full-precision `rand` conversion, and its
`randi` index mapping are implemented directly rather than delegated to a C++
standard-library distribution. Sample coordinates therefore stay reproducible
across C++ standard-library implementations and match the corresponding
MATLAB streams. Floating-point reductions can still differ in their last
digits because of compiler math; elapsed times are inherently machine- and
worker-count dependent. Parallel execution does not change the stored row
order or task-specific stochastic stream.

The vector reports are generated directly in C++ through Cairo's PDF surface.
No MATLAB Runtime, Python plotting process, GUI, or shell worker participates
in either the computation or reporting pipeline.

Finally, histogram, correlation, entropy, NPCR/UACI, and PSNR are statistical
evaluation tools, not a cryptographic security proof. The XOR-only transform
is linear over GF(2); this project should be treated as an implementation and
evaluation port, not as a recommendation for production cryptography.
